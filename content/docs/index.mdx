## Base URL

```text
https://api.apipool.dev/v1
```

Use the APIPool Base URL with the API key created in your APIPool portal.

## Authentication

Send your key in the `Authorization` header:

```text
Authorization: Bearer $APIPOOL_API_KEY
```

The portal only shows the full key once after creation. The key list shows a
masked value afterward.

## curl

```bash
curl https://api.apipool.dev/v1/chat/completions \
  -H "Authorization: Bearer $APIPOOL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"Hello from APIPool"}]}'
```

## JavaScript

```ts
const response = await fetch("https://api.apipool.dev/v1/chat/completions", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.APIPOOL_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4o-mini",
    messages: [{ role: "user", content: "Hello from APIPool" }],
  }),
});

console.log(await response.json());
```

## Python

```python
import os
import requests

response = requests.post(
    "https://api.apipool.dev/v1/chat/completions",
    headers={
        "Authorization": f"Bearer {os.environ['APIPOOL_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "gpt-4o-mini",
        "messages": [{"role": "user", "content": "Hello from APIPool"}],
    },
)

print(response.json())
```

## Common States

- `401`: the key is missing, invalid, disabled, or deleted.
- `403`: the key does not have access to the requested model.
- `429`: the account or upstream route is rate limited.
- `402` or quota errors: the account needs an operator-applied quota adjustment.

## MVP Billing Note

Self-service payment is not enabled in the MVP. New users start with zero quota.
An operator applies quota manually, and the portal records that adjustment in the
APIPool ledger v0.
