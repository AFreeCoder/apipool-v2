# APIPool_v2 最小用户可用版本需求草案 v2

> 承接 02-mvp.md。MVP 已完成最小可部署的垂直闭环；本版本聚焦补齐「真实用户可自助、可信赖使用」所必需的能力。

## 1. 目标定义

最小用户可用版本的目标是让真实用户可以完成：

`注册/登录 → 在线充值或获得管理员发放额度 → 查看模型和价格 → 选择分组创建 API Key → 真实调用模型 → 在控制台看到余额、用量和 Key 状态`

本版本必须支持在线支付，同时保留管理员手动调整额度能力，用于人工充值、补偿、扣减和异常处理。

## 2. 用户侧需求

### 2.1 模型与价格页 `/models`

`/models` 用于展示 APIPool 当前可用模型、价格、分组和状态。

筛选层级：

1. 供应商：OpenAI、Anthropic、Google，可由控制台配置
2. 分组：official、限时折扣 1、限时折扣 2，可由控制台配置
3. 能力：文本、图片、视频、语音，可由控制台配置
4. 状态：可用、即将上线、已下线，可由控制台配置

展示要求：

- 同一个模型 ID 可以在不同分组下重复出现。
- 同一个模型 ID 在不同分组下可以有不同价格、折扣、状态和说明。
- 表格至少展示：模型 ID、供应商、分组、能力、输入价格、输出价格、折扣说明、状态。
- 分组需要有用户可理解的说明，例如 official 表示稳定路线，限时折扣表示价格更低但可能有库存或下线风险。
- “可用”模型允许用户创建 Key 后调用。
- “即将上线”只展示，不允许调用。
- “已下线”默认不推荐展示，不允许新建 Key 调用；如已有 Key 受影响，需要在控制台提示。

### 2.2 控制台 `/dashboard`

控制台需要覆盖用户最小自助使用闭环。

首页概览：

- 展示当前余额或额度。
- 展示最近用量概览：请求数、Token、消费金额。
- 展示 API Base URL。
- 提供充值、创建 API Key、查看用量的入口。

API Key 管理：

- 用户创建 API Key 时必须选择分组。
- 创建 Key 时展示该分组下可用模型范围。
- 只要用户账号可登录，就允许创建 API Key；邮箱是否已验证不作为创建 Key 的前置条件。
- Key 列表展示：名称、掩码 Key、所属分组、允许模型、状态、创建时间。
- 用户可以复制 Key、禁用 Key、删除 Key。
- Key 创建成功后，完整 Key 只展示一次。

余额与充值：

- 用户可以在线充值。
- 充值后余额需要在控制台可见。
- 充值记录需要展示订单时间、金额、支付状态和到账状态。
- 支付成功但额度未到账时，需要展示“到账处理中”或等价状态。
- 余额不足时，用户需要看到明确提示。

用量记录：

- 用户可以看到最近调用记录。
- 每条记录至少包含：时间、模型、Key、状态、Token、消费金额。
- 用户可以看到按模型聚合的用量分布。
- 调用后余额和用量需要能反映实际变化。

### 2.3 登录注册

支持三种登录方式：

- Google 登录
- GitHub 登录
- 邮箱注册/登录

邮箱注册要求：

- 邮箱注册使用邮件链接验证。
- 邮箱链接验证用于确认邮箱归属和提升账号可信度，但不阻止已登录用户创建 API Key。
- 当前版本不做验证码输入流程。
- 邮箱服务需要可在控制台配置。

登录一致性：

- Google、GitHub、邮箱注册后的用户权益一致。
- 不按登录渠道区分额度、价格或可用模型。

## 3. 管理员侧需求 `/admin`

### 3.1 模型目录管理

管理员可以维护供应商、分组、能力和状态。

供应商管理：

- 新增、编辑、禁用供应商。
- 供应商至少包含名称、标识、排序、状态。

分组管理：

- 新增、编辑、禁用分组。
- 分组至少包含名称、标识、用户可见说明、排序、状态。
- 门户分组需要能配置和后台网关分组的对应关系。
- 分组可以标记是否允许用户创建 Key。

能力管理：

- 新增、编辑、禁用能力标签。
- 首批能力为：文本、图片、视频、语音。

模型管理：

- 管理员可以按“供应商 + 分组”添加模型 ID。
- 管理员可以为每个模型 ID 设置单独价格和折扣。
- 管理员可以为模型打能力标签。
- 管理员可以设置模型状态：可用、即将上线、已下线。
- 管理员可以填写用户可见说明，例如稳定性、有效期、限时折扣说明。
- 管理员可以控制模型是否在 `/models` 公开展示。
- 模型上线前需要能标记是否已经完成真实调用验证。

### 3.2 支付与额度运营

管理员需要能支撑在线支付和人工额度处理。

在线支付：

- 支持用户在线充值。
- 支持查看支付订单、支付状态、到账状态。
- 支持支付成功后的额度入账。
- 支持支付回调重复发送时不重复入账。
- 支持支付成功但额度入账失败后的重试或人工处理。

管理员额度调整：

- 管理员可以给用户增加额度。
- 管理员可以扣减用户额度。
- 每次额度调整必须记录操作人、目标用户、调整金额、原因和时间。
- 管理员可以查看用户额度调整历史。
- 管理员调整额度后，用户控制台余额需要可见。

用户与异常处理：

- 管理员可以查看用户列表。
- 管理员可以查看用户余额或额度。
- 管理员可以查看用户 API Key。
- 管理员可以查看用户最近用量。
- 管理员可以处理 Key 创建失败、额度同步失败、用量同步失败等异常。

### 3.3 登录与邮件配置

管理员可以配置：

- Google OAuth Client ID / Secret
- GitHub OAuth Client ID / Secret
- 邮箱服务配置（沿用现有 Resend 云邮件，本版本不引入通用 SMTP）
- 邮箱链接验证开关
- 邮件发送方名称和发送邮箱

配置后，管理员需要能通过最小方式确认邮件服务可用，例如发送测试邮件。

## 4. 验收标准

用户验收：

- 新用户可以完成 Google、GitHub 或邮箱注册登录。
- 邮箱注册用户可以收到验证链接。
- 已登录用户可以创建 API Key，不因邮箱未验证被阻止。
- 用户可以在线充值并看到余额变化。
- 用户可以在 `/models` 找到至少一个可用模型。
- 用户可以选择分组创建 API Key。
- 用户可以复制 Key，并真实调用至少一个模型成功。
- 调用后，用户可以在 `/dashboard` 看到余额减少和用量记录。
- 用户禁用 Key 后，该 Key 不能继续调用。

管理员验收：

- 管理员可以新增供应商、分组、能力和模型。
- 管理员可以让同一个模型 ID 出现在不同分组下，并配置不同价格。
- 管理员可以配置门户分组和后台网关分组的对应关系。
- 管理员可以把模型从“即将上线”改为“可用”，并让用户创建 Key 后调用。
- 管理员可以下线模型或分组，并让用户侧看到明确状态。
- 管理员可以配置 Google、GitHub 和邮箱链接验证服务。
- 管理员可以查看支付订单和到账状态。
- 管理员可以对用户额度执行增加和扣减。
- 管理员可以查看额度调整记录和用户用量。

## 5. 本版本明确不做

- 不把快速接入文档 `/docs` 作为本阶段紧迫项。
- 不做邮箱验证码输入流程。
- 不做每个模型的独立详情页。
- 不做 Playground。
- 不做团队/组织账户。
- 不做用量导出。
- 不做复杂发票系统。
- 不做复杂营销活动系统。
- 不做现有 APIPool 老用户资产迁移。
- 不向普通用户暴露后台网关名称、后台网关管理入口或内部 ID。

## 6. 默认假设

- 在线支付进入本版本范围。
- 管理员额度调整同时支持增加和扣减。
- 分组是用户可感知的价格/渠道选择，不只是后台内部字段。
- 同一个模型 ID 在不同分组下视为不同售卖项。
- 后台网关（New API）不提供「读取分组 / 模型 / 价格列表」的接口；模型目录、分组、价格由门户自行维护一份，管理员在门户与网关两侧手动对齐，本版本不做两者之间的自动同步。
- 首批至少需要一个分组、一个供应商、一个模型完成真实调用验证。
- 邮箱验证沿用当前项目已有的邮件链接验证，不新做验证码输入。
- 邮箱链接验证不作为 API Key 创建权限门槛。
