## 1. 版本目标

这一版不是完整 AI Gateway 平台，而是上线一个真实用户可自助、可信赖使用的最小版本。

APIPool_v2 在本阶段定位为面向用户和管理员的门户：用户在门户里登录、充值、查看模型、创建 Key、看账单和用量；真实 API 调用、渠道路由、底层模型服务、网关级运营监控由 New API 承担。门户需要和 New API 对齐用户、API Key、分组和额度，但不在本版本重做 New API 已经承担的网关能力。

用户最小闭环：

`注册/登录 -> 在线充值或获得管理员发放额度 -> 查看模型和价格 -> 选择分组创建 API Key -> 真实调用模型 -> 在控制台看到余额、用量和 Key 状态`

本版本的核心范围分为六个方面：

1. 模型广场：用户可以查看不同分组的模型清单、价格和折扣。
2. 登录：用户可以完整注册、登录并进入控制台。
3. 支付与额度：用户可以在线充值，管理员可以人工增减额度和处理异常。
4. API Key：用户可以创建和管理 API Key，并与 New API 的 Key、分组保持对齐。
5. 控制台账单与 Token 消费：用户可以看到余额、账单、Token 消费和基础用量。
6. 管理员最小管理：管理员可以维护目录、配置登录邮件、查看用户和处理关键异常。

## 2. 用户侧需求

### 2.1 模型广场 `/models`

`/models` 用于展示 APIPool 当前可售卖模型、价格、分组、折扣和状态。

基础筛选和展示维度：

1. 供应商：OpenAI、Anthropic、Google，可由控制台配置。
2. 分组：official、限时折扣 1、限时折扣 2，可由控制台配置。
3. 分类：LLM、图片、视频、语音等，可由控制台配置。
4. 能力：文本、图片、视频、语音等，可由控制台配置。
5. 状态：可用、即将上线、已下线，可由控制台配置。

展示要求：

- 同一个模型 ID 可以在不同分组下重复出现。
- 同一个模型 ID 在不同分组下可以有不同价格、折扣、状态和说明。
- 同一个“模型 ID + 分组”视为一个独立售卖项。
- 表格至少展示：模型 ID、供应商、分组、分类、能力、输入价格、输出价格、折扣说明、状态。
- 分组需要有用户可理解的说明，例如 official 表示稳定路线，限时折扣表示价格更低但可能有库存或下线风险。
- 折扣说明由管理员维护；没有折扣时展示标准价格，不制造“限时”或“优惠”心智。
- 如有划线价或限时折扣说明，必须和该售卖项的实际价格一致。
- “可用”模型允许用户创建 Key 后调用。
- “即将上线”只展示，不承诺可调用，不作为创建 Key 的可用范围。
- “已下线”默认不推荐展示，不允许新建 Key 调用；如已有用户受影响，控制台需要给出明确状态提示。
- 普通用户不应看到 New API 后台名称、后台入口、内部 ID 或 `newapiGroup`。

首发要求：

- 本版本不要求硬编码固定模型清单，模型目录由管理员在 `/admin` 维护。
- 上线前至少需要配置 1 个供应商、1 个分组、1 个可用模型售卖项，并完成真实调用验证。
- 后台需要支持供应商、分组、分类、能力、模型、售卖项、价格、折扣和状态的基础增删改查。

### 2.2 登录注册

支持三种登录方式：

- Google 登录。
- GitHub 登录。
- 邮箱注册/登录。

邮箱注册要求：

- 邮箱注册使用邮件链接验证。
- 邮箱链接验证用于确认邮箱归属和提升账号可信度。
- 只要用户已登录，就允许创建 API Key；邮箱是否已验证不作为 API Key 创建前置条件。
- 当前版本不做验证码输入流程。
- 邮箱服务沿用 Resend，并需要可在管理员控制台配置。

登录一致性：

- Google、GitHub、邮箱注册后的用户权益一致。
- 不按登录渠道区分额度、价格或可用模型。

### 2.3 控制台 `/dashboard`

控制台覆盖用户最小自助使用闭环。

首页概览：

- 展示当前余额或额度。
- 展示最近用量概览：请求数、输入 Token、输出 Token、消费金额。
- 展示 API Base URL。
- 提供充值、创建 API Key、查看用量的入口。
- 当用量同步失败或数据过期时，需要展示“同步中 / 暂无用量 / 数据可能延迟 / 同步失败”等可理解状态。

API Key 管理：

- 用户创建 API Key 时必须选择门户分组 `groupSlug`。
- 服务端根据 `groupSlug` 映射到 New API 分组，创建远端 Key 并保存本地绑定关系。
- 创建 Key 时可以展示该分组下当前可用模型范围，但这只是帮助用户理解分组能调用什么。
- 本版本的 API Key 只绑定用户和分组，不做模型级授权限制、单 Key 余额限制、单 Key budget 或 rate limit。
- Key 创建成功后，完整 Key 只展示一次。
- Key 列表展示：名称、掩码 Key、所属分组、可用模型范围说明、状态、创建时间。
- 用户可以复制 Key、禁用 Key、删除 Key。
- Key 创建、禁用、删除失败时，需要保留可诊断状态，允许用户或管理员清理失败记录。

余额与充值：

- 用户可以在线充值。
- 充值后余额需要在控制台可见。
- 充值记录需要展示订单时间、金额、支付状态和到账状态。
- 支付成功但额度未到账时，需要展示“到账处理中”或等价状态。
- 支付或到账失败时，需要展示可理解状态，不能让用户误以为已成功入账。
- 余额不足时，用户需要看到明确提示。
- 管理员手动增减额度后，用户控制台余额需要可见。

用量记录：

- 用户可以看到最近调用记录。
- 每条记录至少包含：时间、模型、Key、状态、输入 Token、输出 Token、消费金额。
- 用户可以看到按模型聚合的用量分布。
- 调用后余额和用量需要能反映实际变化。
- 用量同步需要避免重复计算同一条调用记录。

## 3. 管理员侧需求 `/admin`

### 3.1 模型目录管理

管理员可以维护供应商、分组、分类、能力和模型售卖项。

供应商管理：

- 新增、编辑、禁用供应商。
- 供应商至少包含名称、标识、排序、状态。

分组管理：

- 新增、编辑、禁用分组。
- 分组至少包含名称、标识、用户可见说明、排序、状态。
- 门户分组需要配置到 New API 分组的对应关系。
- 分组可以标记是否允许用户创建 Key。
- 门户分组与 New API 分组由管理员两侧手动对齐；本版本不做自动同步。

分类管理：

- 新增、编辑、禁用模型分类。
- 分类用于帮助管理员和用户理解模型用途，例如 LLM、图片、视频、语音。
- 分类不承担 New API 路由语义，不需要和 New API 字段对齐。

能力管理：

- 新增、编辑、禁用能力标签。
- 首批能力为：文本、图片、视频、语音。

模型管理：

- 管理员可以按“供应商 + 分组”添加模型 ID。
- 管理员可以为每个模型售卖项设置单独价格和折扣。
- 管理员可以为模型打能力标签。
- 管理员可以设置模型状态：可用、即将上线、已下线。
- 管理员可以填写用户可见说明，例如稳定性、有效期、限时折扣说明。
- 管理员可以控制模型是否在 `/models` 公开展示。
- 模型上线前需要能标记是否已经完成真实调用验证。

### 3.2 支付与额度运营

管理员需要能支撑在线支付、人工额度处理和异常救援。门户只负责展示和处理与订单、账本、Key、用户绑定相关的状态；网关运行质量、模型渠道可用性和 API 请求告警优先使用 New API 自身能力。

在线支付：

- 支持用户在线充值。
- 支持查看支付订单、支付状态、到账状态。
- 支持支付成功后的额度入账。
- 支持支付回调重复发送时不重复入账。
- 支持支付成功但额度入账失败后的重试或人工处理。
- 支持记录支付流水、账本流水、远端额度调整结果和错误信息。

管理员额度调整：

- 管理员可以给用户增加额度。
- 管理员可以扣减用户额度。
- 每次额度调整必须记录操作人、目标用户、调整金额、原因和时间。
- 管理员可以查看用户额度调整历史。
- 管理员调整额度后，用户控制台余额需要可见。

异常处理：

- 管理员可以查看用户列表。
- 管理员可以查看用户余额或额度。
- 管理员可以查看用户 API Key。
- 管理员可以查看用户最近用量。
- 管理员可以处理 Key 创建失败、远端 Key 已创建但本地绑定失败、额度同步失败、用量同步失败等异常。
- 异常处理需要留下审计记录，避免二次补偿或重复入账。
- 本版本不要求门户建设独立告警平台；需要主动监控的网关请求、渠道健康、模型错误率优先使用 New API 或现有基础设施。

### 3.3 登录与邮件配置

管理员可以配置：

- Google OAuth Client ID / Secret。
- GitHub OAuth Client ID / Secret。
- 邮箱服务配置，即 Resend，本版本不引入通用 SMTP。
- 邮箱链接验证开关。
- 邮件发送方名称和发送邮箱。

配置后，管理员需要能通过最小方式确认邮件服务可用，例如发送测试邮件。

## 4. 状态与错误处理基线

### 4.1 API Key 管理范围

本版本的 API Key 产品范围保持简单：创建、查看、复制、禁用、删除。复杂的单 Key 额度限制、模型级权限、预算、限速、自动恢复等能力不进入 user-mvp。

用户可见状态至少覆盖：

| 状态 | 含义 | 用户侧行为 |
| --- | --- | --- |
| 创建中 | 正在创建远端 Key | 展示处理中，不展示完整 Key |
| 可用 | 本地与 New API 均可用 | 可复制、禁用、删除 |
| 禁用中 | 正在同步禁用到 New API | 展示处理中，避免重复点击 |
| 已禁用 | 已禁用，不应继续调用 | 可删除；如需继续使用，重新创建 Key |
| 删除中 | 正在删除远端或清理本地绑定 | 展示处理中，避免重复操作 |
| 已删除 | 已删除 | 默认不在用户列表展示 |
| 创建或同步失败 | 创建、禁用或删除没有完成 | 展示失败原因摘要，允许清理或由管理员处理 |

最低要求：

- 完整 Key 只展示一次。
- 禁用或删除操作不能只改本地状态，必须尽力同步 New API。
- 远端同步失败时不能静默成功，必须保留错误状态。
- 已删除 Key 不再作为可用 Key 展示。
- 用户无需理解内部状态名；内部状态机只要能支撑上述用户可见状态和管理员排障即可。

### 4.2 支付与额度状态

支付与额度至少区分订单支付状态和额度到账状态。

- 支付状态表示用户是否完成付款。
- 额度到账状态表示账本是否已成功应用到用户额度。
- 支付回调必须幂等，重复回调不能重复加额。
- 账本流水需要能表达 `pending`、`applied`、`failed`。
- 支付成功但额度未到账时，用户侧展示到账处理中。
- 入账失败需要进入可重试或人工处理队列。
- `pending` 期间用户调用可能因余额不足失败，提示应指向“充值到账处理中”，而不是误判为未付款。

### 4.3 用量同步状态

用量同步至少需要表达：

- `ready`：用量可展示。
- `empty`：当前暂无用量。
- `syncing`：正在同步。
- `stale`：已有数据但可能延迟。
- `failed`：同步失败，用户或管理员可看到错误状态。

用量统计至少覆盖请求数、输入 Token、输出 Token、消费金额、按模型聚合，并避免重复计算同一远端调用记录。

## 5. 验收标准

### 5.1 用户验收

- 新用户可以完成 Google、GitHub 或邮箱注册登录。
- 邮箱注册用户可以收到验证链接。
- 已登录用户可以创建 API Key，不因邮箱未验证被阻止。
- 用户可以在 `/models` 找到至少一个可用模型，并看到分组、价格和折扣。
- 用户可以选择分组创建 API Key。
- 用户可以复制 Key，并真实调用至少一个模型成功。
- 用户禁用 Key 后，该 Key 不能继续调用。
- 用户删除 Key 后，列表不再把它展示为可用 Key。
- 用户可以在线充值并看到余额变化。
- 支付成功但额度未到账时，用户能看到到账处理中。
- 调用后，用户可以在 `/dashboard` 看到余额减少、输入/输出 Token 和用量记录。
- 用量为空、同步中、延迟或失败时，用户看到明确状态。

### 5.2 管理员验收

- 管理员可以新增供应商、分组、分类、能力和模型。
- 管理员可以让同一个模型 ID 出现在不同分组下，并配置不同价格。
- 管理员可以配置门户分组和 New API 分组的对应关系。
- 管理员可以把模型从“即将上线”改为“可用”，并让用户创建 Key 后调用。
- 管理员可以下线模型或分组，并让用户侧看到明确状态。
- 管理员可以配置 Google、GitHub 和邮箱链接验证服务。
- 管理员可以查看支付订单、账本流水和到账状态。
- 管理员可以对用户额度执行增加和扣减。
- 管理员可以查看额度调整记录和用户用量。
- 管理员可以识别并处理 Key 创建失败、入账失败、用量同步失败。

### 5.3 外部依赖验收

本地测试应覆盖门户功能、New API 对齐逻辑、账本幂等、Key 创建/禁用/删除、用量同步和真实或等价 New API 调用链。以下能力必须由人类在真实或沙箱环境中验收：

- OAuth：Google、GitHub 需要真实 Client 配置。
- 邮件：Resend 需要真实发送配置。
- 支付：支付 Provider 和 webhook 需要真实或沙箱环境。

其他验收应尽量自动化或通过本地等价环境验证：

- New API：可以使用真实或本地等价 New API 环境验证，且门户分组与 New API group 已对齐。
- 真实调用：至少一个 provider、一个分组、一个模型需要完成真实或等价烟测调用验证。

发布前的 live smoke 以运行手册和开发记录为准；需要真实 New API 烟测环境时，使用：

```bash
APIPOOL_SMOKE_REQUIRE_LIVE=true npm run smoke:mvp
```

## 6. 本版本明确不做

- 不把快速接入文档 `/docs` 作为本阶段紧迫项。
- 不做邮箱验证码输入流程。
- 不做每个模型的独立详情页。
- 不做 Playground。
- 不做团队/组织账户。
- 不做用量导出。
- 不做复杂发票系统。
- 不做复杂营销活动系统。
- 不做现有 APIPool 老用户资产迁移。
- 不向普通用户暴露后台网关名称、后台网关管理入口、内部 ID 或 `newapiGroup`。
- 不做门户模型/价格/分组与 New API 的自动同步。
- 不做分组连通性自动自检。
- 不做 Key 级别的精确受影响模型分析。
- 不做模型级 API Key 权限、单 Key 余额限制、单 Key budget 或 rate limit。
- 不做 WebSocket 或自动轮询来实时刷新余额、用量和 Key 状态。
- 不做完整 routing、fallback、Playground、budget、rate limit、observability 平台化能力。
- 不做门户侧独立告警平台；网关请求告警和渠道监控优先使用 New API 或现有基础设施。

## 7. 默认假设

- 在线支付进入本版本范围。
- 管理员额度调整同时支持增加和扣减。
- 分组是用户可感知的价格/渠道选择，不只是后台内部字段。
- 同一个模型 ID 在不同分组下视为不同售卖项。
- New API 不提供“读取分组 / 模型 / 价格列表”的接口；模型目录、分组、价格由门户自行维护一份。
- 管理员负责在门户与 New API 两侧手动对齐分组和可用模型。
- 首批至少需要一个分组、一个供应商、一个模型完成真实调用验证。
- 邮箱验证沿用当前项目已有的邮件链接验证，不新做验证码输入。
- 邮箱链接验证不作为 API Key 创建权限门槛。
- New API 额度单位、账本幂等和回滚策略以支付与额度账本文档为准。
- New API 是本版本的实际 API 网关；门户不接管底层 API 请求路径。

## 8. 12 个月方向，不进入 user-mvp

以下方向重要，但不作为本版本上线门槛：

- 模型路由、fallback 和动态供应商选择。
- 用户级 budget、rate limit 和更复杂的成本控制。
- 完整观测、告警、运营 dashboard 和异常自动化。
- 团队、组织、成员权限和企业账单。
- 完整开发者文档、Playground、SDK 示例和迁移工具。
- 用量导出、发票、营销活动和客户生命周期运营。
