## 1. 产品目标

用户应能完成以下自助闭环：

`注册/登录 → 查看模型与价格 → 充值或获得管理员调额 → 选择分组创建 Portal Key → 调用 APIPool → 查看余额、用量与账单 → 禁用或删除 Key`

APIPool 是用户入口、鉴权与计费事实源：

- Portal Key、门户钱包、请求账本和售卖价格均由 APIPool 管理。
- New API 是内部上游网关，负责渠道路由和内部运行凭证，不向普通用户暴露。
- New API `username` 必须等于门户规范化邮箱；不得截断、哈希或使用技术别名。
- 门户钱包是用户资产唯一事实源，New API quota 只作为与钱包解耦的内部运行池。

## 2. 模型目录与定价

- `/models` 展示当前可售卖的供应商、模型、分类、能力、分组、状态和价格。
- 同一模型 ID 可以在不同门户分组下形成独立售卖项，并选择不同定价档案。
- 不同分组可使用不同计费方式、价目表、折扣和 New API 分组映射。
- 上游成本同步不得自动修改售卖价、隐藏已确认售卖项或改变 listing 可调用状态。
- “可用”模型必须具备当前分组下完整、已确认的售价与上游映射；“即将上线”和“已下线”不得作为新调用入口。
- 普通用户不得看到 New API 后台名称、内部 ID、`newapiGroup`、成本价或运行凭证。

## 3. 登录与身份

- 支持 Google、GitHub 和邮箱注册/登录；各登录渠道权益一致。
- 邮箱链接验证用于确认邮箱归属，但已登录用户创建 Portal Key 不以邮箱验证状态为前置条件。
- 服务端以 `email.trim().toLowerCase()` 作为 New API username；邮箱过长被上游拒绝时，应修复 New API 兼容性，不得改写用户名规避。
- OAuth、邮件与认证 secret 只在服务端和管理员设置中使用，不下发到用户侧。

## 4. Portal Key 与调用

- 用户创建 Portal Key 时必须选择门户分组 `groupSlug`。
- Portal Key 只绑定用户和门户分组，完整明文只在创建成功时展示一次，数据库只保存哈希和掩码。
- 服务端按“门户分组 × 模型”解析当前售卖项、价格快照和 New API 分组，并按“用户 × New API 分组”复用内部运行凭证。
- 用户不能取得 New API token；Portal Key 的创建、禁用和删除不与远端 token 一一绑定。
- 禁用或删除 Portal Key 后，网关必须立即拒绝该 Key；删除后的 Key 不再作为可用 Key 展示。
- 本阶段不提供单 Key 余额、单 Key budget、单 Key rate limit 或模型级授权列表。

## 5. 钱包、支付与账单

- `wallet_account` 与追加式 `wallet_ledger` 是用户余额事实源，金额使用整数 micro-USD。
- 充值、请求扣费、冲正和人工调整都必须写钱包流水，并与余额物化值保持原子一致。
- 支付订单状态和钱包入账状态必须区分；支付成功但尚未入账时显示“到账处理中”。
- 重复支付回调、重复网关终态或重复后台任务不得重复入账或扣费。
- 对用户未成功的请求不扣费；无法归因的上游消费进入独立对账观察，不伪造请求账本。
- 用户能查看余额、充值记录、请求记录、模型、Token/数量用量和消费金额。

## 6. 管理员能力

- 维护供应商、分组、分类、能力、状态、模型、定价档案和售卖项。
- 维护每条“模型 × 门户分组”的 New API 分组映射和可调用状态。
- 查看用户、Portal Key、钱包、请求账本、支付订单和对账异常。
- 执行有理由、有审计、可幂等的人工调额、冲正、冻结和解冻。
- 处理运行凭证失效、孤儿消费、计价不完整、路由不可用和支付入账异常。
- 所有管理能力必须受 RBAC 保护，资金和凭证操作不得静默失败。

## 7. 用户状态与错误体验

- 余额不足、账户冻结、Key 无效、模型不可用、请求过大、上游故障和内部错误必须有稳定错误码。
- 用户错误不得泄漏 New API token、管理员 token、内部域名、内部 ID、内部分组或上游凭证错误体。
- 用量为空、处理中、延迟或失败时必须明确展示状态，不能把失败伪装成成功的零用量。
- 后台保留可排障的请求 ID、账本关联、价格版本和审计信息。

## 8. 发布验收边界

- 至少一个供应商、一个门户分组和一个模型售卖项完成真实调用与本地账本闭环。
- Portal Key 创建、调用、用量可见、扣费、禁用后拒绝均通过生产 live smoke。
- 生产冒烟只使用 [运行手册](07-runbook.md#32-自动化-mvp-smoke) 定义的唯一固定身份，不另建临时测试账户。
- 支付、OAuth、邮件和浏览器 UI 需要在相应真实或沙箱环境中验收。
- 发布失败必须能回滚到上一稳定镜像和配置；用户钱包、请求账本与审计历史不得因回滚丢失。

## 9. 非目标

- 不做旧 APIPool 用户资产自动迁移。
- 不向普通用户开放 New API 管理面或原生 token。
- 不建设团队/组织、企业账单、Playground、复杂发票或完整运营自动化。
- 不因未来可能需要而预建多币种、时段价、用户级折扣或复杂策略引擎。
