## 结论

**本轮不通过，不建议发布。**

基础文本调用、Embedding 调用、sub2api 调用、门户钱包结算、运行池自动供应、Key 生命周期、管理端保存和低成本长上下文双态均已跑通。发布前仍有 1 个本轮新发现的主要缺陷，以及 Images、web search、`gpt-5.6-luna`、真实 272K+ 长上下文等能力级门禁未闭环：

1. **成本参照同步会让 Embedding 的公开卖价消失。** 同步前公开页正确显示 `$0.02 / 1M input`；同步成功后数据库里的门户卖价仍是 `20000 micro-USD / 1M`，但公开页变为 `— / —`。实际 New API 参照把 `source_supported_endpoint_types` 刷为 `["openai"]`，公开查询又依赖该字段识别 Embedding-only，导致输出价为空时把整组价格隐藏。该问题违反“成本守卫不得影响门户卖价展示”。
2. **Images 能力级门禁仍未通过。** RunAPI 的真实长 URL 结算已通过，但请求 `n=1` 时生成和编辑均实际返回 2 张图；网关按真实 `data.length=2` 正确扣了 `$0.02`。显式请求 `b64_json` 仍返回 URL，符合当前 RunAPI 通道只返回 URL 的既有调研结论，但不能替代另一真实 `b64_json` 上游的验收证据。
3. **能力级真实证据仍有缺口。** `gpt-5.6-luna` 未在本地目录中；web search 仅验证未配价时 400 fail-closed；长上下文仅用 200-token 阈值夹具完成双态，未执行 272K+ 真请求。

## 核心用户闭环

### 注册、钱包、运行池与首次调用

1. 全新用户注册成功，自动建立门户钱包和 New API 用户绑定。
2. Checkout 关闭时，控制台首页和余额页不显示充值按钮或余额提醒。
3. 用户创建 Official Key，明文只展示一次，列表只显示掩码。
4. 第一次真实 Chat Completions 调用返回 `503` 和 `Retry-After: 1`，提示运行凭据准备中。
5. 未修改远端用户数据，稍后重试返回 `200`；运行池自动供应到目标水位并写入唯一一次脱敏 `newapi.runtime_pool.provision` 审计。
6. 首次成功请求按 11 input / 16 output 结算 `91 micro-USD`，用量页、账单页、请求账本与钱包扣费一致。

该链路满足“注册 → 仅本地钱包入账 → 创建 Key → 运行池自动供应 → 首次真实调用 → 门户结算”的通用硬门。目标 New API 的可变标签虽为 `latest`，本报告已固定记录实际镜像 ID 与实例版本。

### Key 生命周期和权限

- 无效 Key 返回 401。
- Official Key 调用 sub2api 模型、sub2api Key 调用 Official 模型均返回 404。
- Key 在页面停用后立即返回 401；删除后继续返回 401。
- 删除确认弹窗明确说明立即吊销且不可恢复。
- 普通用户访问 `/zh/admin` 跳转到中文无权限页。
- 错误密码显示中文错误；正确密码可重新登录。
- 退出登录最终跳转公开首页，私有数据不再可见；先前一次即时快照中的短暂旧内容未能稳定复现，不列为缺陷。

- token 模型长上下文阈值从 200 改为 201 后保存、持久化、重定向成功，随后已恢复 200。

- 网关运营页“请求、对账、指标、审计”中文标签完整；对账页钱包不变量正常。
