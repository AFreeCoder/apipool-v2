# APIPool UI/UX 专业审查报告（2026-07-08）

> 审查方式：本地起站（`pnpm dev`，sqlite + `NEWAPI_INTEGRATION_ENABLED=false`），Playwright 无头 Chromium 实拍 20 张截图（桌面 1440×900 / 移动 375×812，明暗双主题，登录/登出双状态），结合源码核对。证据截图见 `docs/test/ui-review/shots/`。本报告只提建议，不改代码。
>
> 范围：营销页（首页 / models / docs）、认证页、用户控制台（概览 / API 密钥 / 余额 / 用量）、移动端。管理后台本轮未重新截图（本地提权操作被会话权限策略拦截；其顶栏切换器已在 2026-06-27 轮统一过）。
>
> 局限：本地目录只有 1 个模型、无用量数据，表格密度与图表观感无法完全评估，相关结论已标注。

## 总评

**当前约 68–72 分。** 底子是好的：`docs/05-design-system.md` 的"开发者工具风、单一绿强调、mono 表达机器可读"定位清晰，营销页和控制台大体执行到位，暗色模式完成度高，布局无硬伤。**拖后腿的不是"设计得丑"，而是"没有收尾"**——差距集中在五件事：

1. **头部控件区杂乱**（用户点名的例子，诊断见下）；
2. **三套壳并存**：营销站 / fumadocs 文档 / 认证页各一套头部与控件，跨页像换了网站；
3. **品牌识别度趋零**：纯文字 logo、无 signature 记忆点、供应商行是裸文本；
4. **细节未收口**：空态无行动、错误提示英文裸奔、`USD $10` 双重货币符、筛选值漏翻；
5. **语言检测横幅**视觉权重过高且在认证页盖住页头（实现缺陷）。

这五件事都属于"改造面小、观感提升大"的范畴，收拾完可稳过 80。

## 一、右上角控件区（重点诊断）

现状（`src/features/apipool-ui/site-shell.tsx:47-64`，证据 `10-dashboard-light-full.png`、`19-avatar-dropdown.png`）：

```
[🌙]  [🌐 中文]  (U)  [控制台 →]        ← 登录态
[🌙]  [🌐 中文]  [登录]  [控制台 →]     ← 登出态
```

### 为什么显得乱

1. **三种视觉语言硬拼在一起**：主题切换是"裸图标"（无边框，`AnimatedThemeToggler`），语言是"带边框 icon+文字 pill"（`LocaleSelector type="button"`），旁边又是圆形头像和另一个带边框按钮。四个元素高度、留白、有无边框全不统一，视觉上没有"组"的概念。
2. **信息架构没分层**：主题/语言是低频的"偏好设置"，控制台是高频的"核心动线"，头像是"身份"。三类东西平铺在同一行同一视觉权重，用户扫过去抓不到重点。
3. **登出态双 CTA 冗余**：`登录`（primary）和 `控制台 →`（outline）在登出时点进去都是登录页——同一目的地两个按钮。
4. **登录态"控制台"按钮不知情**：已经在 /dashboard 里，头部仍然显示"控制台 →"引导按钮（`10-dashboard-light-full.png`）。
5. **头像菜单是空壳**：下拉只有"名字 + 登出"两项（`19-avatar-dropdown.png`），标准的账户菜单位被浪费——这正是收纳低频控件的最佳位置。

### 建议方案 A（推荐，OpenRouter / Vercel / Stripe 惯例）

顶栏右侧只留 **两个元素**：

```
登录态：  [控制台 →(primary,仅营销页显示)]  (头像)
登出态：  [登录(ghost)]  [开始使用 →(primary)]
```

- 主题、语言全部收进**头像下拉菜单**（登录态）：菜单结构 = 名字/邮箱 → 控制台 / API 密钥 / 余额 / 用量 → 主题(子菜单或行内三态) / 语言(子菜单) → 登出。
- 登出态的主题/语言入口放**页脚**（业界通行，Stripe/Linear 均如此；页脚现在右下角只有一句 tagline，正好有位置）。
- 已在控制台路由下时，营销头部的"控制台"按钮隐藏或变为非按钮的当前态。
- 收益：控件从 4–5 个减到 2 个，"堆在一起"的问题从根上消失，且头像菜单从空壳变成真正的账户中枢。

### 建议方案 B（保守，不动信息架构）

若坚持切换器留在顶栏：

- 主题按钮改用与语言完全相同的规格（同为 `ghost` 或同为 `outline`，统一 `h-9`，图标同 16px）；语言去掉文字只留 🌐 图标（当前语言可用 tooltip 表达），两者组成紧凑 segmented 组；
- 偏好组与 [头像+控制台] 之间加 `border-l` 分隔或加大 gap，制造"偏好 | 身份/动线"两组的视觉分组；
- 登出态删掉"控制台"按钮只留"登录"一个 CTA。

另注意：`ThemeToggler` 的 `type="button"` 形态没有绑定 onClick（`src/shared/blocks/common/theme-toggler.tsx:35-40`），是个点了没反应的死分支，收敛形态时顺手清理。

## 二、全站性问题

### 1. 三套壳不统一（跨模块一致性，P0）

| 区域 | 头部 | 主题/语言控件 | 代码块 |
|---|---|---|---|
| 营销站 SiteShell | 文字 logo + 2 导航 + 控件堆 | 裸图标 + outline pill | 深底终端 |
| /docs（fumadocs 默认壳） | 自己的搜索框居中头部 | fumadocs 自带的另一套小图标 | **浅灰底**（违反 05 规范"代码块深底"） |
| 认证页 | 独立简版头部 | 又一套摆法 | — |

从首页点"文档"，头部、搜索、切换器、代码块样式全变（`05-docs-light-full.png` vs `01-home-light-full.png`）——这是"像模板拼的"观感的最大来源之一。建议：定制 fumadocs 主题令牌复用 `--primary/--font-*/--radius`，头部保留回主站的导航链接，隐藏 fumadocs 自带主题/语言控件（全站只留一套），代码块统一深底终端样式。docs 侧栏目前只有一条目，可考虑先收窄或并入顶部，等文档多了再展开。

### 2. 语言检测横幅（P0）

`src/shared/blocks/common/locale-detector.tsx`：

- **样式**：primary 渐变 + `shadow-lg` 全宽大条（:242），视觉权重压过 header，和"克制"基调冲突（`01-home-light-full.png` 顶部）；明暗主题同一个绿，暗色下更突兀。
- **实现缺陷**：banner 是 `fixed`，靠 JS 改 `header.style.top` 往下推页头（:120-124）。营销页 header 是 sticky 所以有效；**认证页 header 是静态定位，`top` 不生效 → banner 直接盖住 logo 和右上控件**（`06-signin-light.png` 可见登录页页头被盖）。
- 建议：整体降级为流内窄条（header 上方一行浅底 `bg-muted` 提示 + 文字链），或右下角 toast；删掉整套 querySelector hack。横幅文案当前只有英文视角，若保留需双向本地化。

### 3. 品牌识别度（P1）

- 头部只有纯文字 "APIPool"，无品牌图形；`public/logo.png` 仍是模板紫色 ShipAny 图标（与绿色主题冲突，favicon 已换但 logo 未换）。
- 全站最有个性的元素是首页 hero 的深色终端卡（带 `bg-primary/15 blur-2xl` 光晕，`page.tsx:43`）——这是现成的 signature，建议把"终端美学"贯穿全站：docs 代码块、控制台 BASE URL 卡（做成深底终端行 + 复制按钮）都统一这个语言，形成记忆点。
- 供应商行（OpenAI / Anthropic / Google / Qwen / Kimi / MiniMax）是裸 mono 文本，像没写完的占位（`01-home-light-full.png` 中部）；移动端换行更乱（`08-home-mobile-full.png`）。建议换灰度 logo 行（hover 恢复彩色）或至少 pill 化 + 统一间距。

### 4. 文案与本地化收口（P1）

- 创建 Key 失败提示英文裸奔："Create API key is temporarily unavailable. Try again later."（`18-createkey-dialog.png`；API route 直接返回英文串，前端原样展示，`src/app/api/apipool/keys/route.ts`）。错误路径需要走 i18n（错误码 → 前端词条）。
- /models 筛选值中文页漏翻：Embedding / Image / Audio / Video / Rerank / Coming soon / Retired（`03-models-light-full.png`）。
- 创建 Key 输入框 placeholder "你的 API 密钥" 语义错误——这里填的是 **Key 名称**，不是密钥本身（`17-apikeys-light.png`），建议 "Key 名称，如 my-app"。
- 分组选择器直接暴露 "反代 / 官方" 内部术语，无任何解释；至少加 tooltip 或一行说明（价差/稳定性差异），否则新用户无法决策。
- 余额页 "USD $10" 双重货币标记 ×7 处（`12-billing-light-full.png`），改 "$10" 或 "US$10"。

## 三、逐页审查

### 首页（`01/02-home-*.png`）

好的：hero 结构（eyebrow → H1 → 副标题 → 双 CTA → checkmark 行 + 终端卡）是标准且执行到位的开发者产品打法；01/02/03 步骤区、四列价值主张都干净。

问题与建议：

1. 供应商行（见品牌节）。
2. "图像与多媒体生成"卡的 6 块渐变虽然已用 primary 透明度阶梯（合规），但暗色下 `to-primary` 满饱和块过亮刺眼（`02-home-dark-full.png`），建议暗色把上限压到 `primary/70` 左右，或整体统一亮度曲线。
3. 页面节奏单调：四个区块全是"标题 + 网格卡"，建议中段插入一个不同形态的区块（如横向铺满的模型/价格预览表，顺带给 /models 引流），打破"卡片墙"。
4. 四列价值主张的图标 16px 太小、与标题视觉基线不齐，可上调到 20px 并统一与标题的间距。

### /models（`03-models-light-full.png`）

1. **5 行筛选器占了首屏近一半**，违反自家规范"/models 首屏即见表格"（05 §6）。建议压缩为一行：搜索框 + 4 个下拉（供应商/分组/分类/能力）+ 状态默认只显示可用；已选条件用 chips 行展示。本地只有 1 个模型无法评估表格密度，上线数据多时再核行高与 mono 对齐。
2. 筛选值漏翻（见上）。
3. 表格行 hover 有反馈但不可点（详情页是桩）——要么去掉行 hover 避免"可点"的错误暗示，要么尽快补详情页。
4. 价格列上线后务必右对齐 + mono（规范已有，目前 "—" 看不出执行情况）。

### /docs（`05-docs-light-full.png`）

见"三套壳"节。内容本身（Base URL 卡 → 鉴权 → 多语言示例 → 错误码表）结构好，是全站信息密度最健康的页面；只需要壳与代码块样式向主站看齐。

### 认证页（`06-signin-light.png`）

1. banner 盖头（见上，P0 bug 级）。
2. 卡片本身干净；但"重要提示"合规声明是一大块灰底，视觉重量与"登录"主按钮相当，建议降为小字 footnote（`text-xs text-muted-foreground`，不带底色框），law-critical 内容保留即可。
3. 卡内无品牌 mark，页头 logo 又被 banner 盖住，登录页整体"无主"；卡顶部加一行小 logo 即可。

### 控制台

**概览**（`10-dashboard-light-full.png`）：布局（tab → 标题+主操作 → BASE URL → 统计卡 → 最近请求）清晰，密度对。细节：

1. tab "概览" 与 H1 "概览" 紧挨着重复，H1 建议改为"欢迎/账户总览"或直接去掉 H1 只留描述行。
2. BASE URL 卡建议升级为深底终端行 + 复制按钮（当前是浅底 code 块，且没有复制交互——开发者最高频的动作）。
3. "请求数·7天" 卡里的错误文案"用量同步暂不可用，请稍后再试"以正文态出现，建议用 warning 语义（图标 + muted 底），并且不要同时出现在页面副标题位（用量页把它当页面描述展示，观感像页面坏了）。

**API 密钥**（`17/18`）：inline 创建表单方向对；placeholder 语义、分组术语、英文报错见上。表格卡标题 "http://127.0.0.1:3001/v1 的 Key" 把机器 URL 当标题，建议 "API Keys"+副标题展示 Base URL。"脱敏 KEY" 列名偏内部术语，可作 "Key（部分显示）"。

**余额**（`12`）：

1. 一屏两个 primary 按钮（推荐档"充值 USD $50" + "按自定义金额充值"）违反 05 §5 单 primary 规则——自定义充值改 outline。
2. "当前余额"孤卡飘在右上角与 H1 对角，视觉上像遗落元素；建议并入页头行（H1 右侧大数字）或做成统计卡行。
3. `USD $10` 双重货币符（见上）。
4. 充值记录/用量扣费两个空态只有一句灰字；规范要求"一句话 + 一个次按钮"（如"去充值"锚点/刷新）。

**用量**（`11-usage-light-full.png`）：模型分布、请求日志空态同样无行动引导；数据来了之后记得图表用 chart token（本轮无数据未评）。

### 移动端（`08-home-mobile-full.png`、`20-mobile-drawer.png`、`15-dashboard-mobile-full.png`）

1. 头部 [☰][APIPool][登录][控制台→] 四元素挤 375px，登出态只留一个 CTA（登录）即可。
2. 抽屉内容稀疏：两个小字号浅灰链接 + 底部"裸月亮图标 + 带框中文 pill"（不成对问题在抽屉里复现）。建议：导航链接加大到 `text-base` 全宽行；底部做成两行带 label 的设置行（"主题：亮/暗/系统"三态 toggle、"语言：中文 ▾"）；登录/控制台 CTA 也应进抽屉底部。
3. hero 终端代码横向裁切（curl 长行被切在卡边），卡内需 `overflow-x-auto` 或移动端换更短的示例。
4. 控制台移动端（15）表现良好，卡片堆叠正常。

## 四、优先级路线图

**P0——一周内做完，观感立涨（≈ +6~8 分）**

- [ ] 头部控件重组（方案 A 或 B），含头像菜单补全、登出态单 CTA、控制台内隐藏"控制台"按钮
- [ ] 语言横幅降级为流内提示/toast，修复认证页盖头
- [ ] fumadocs 壳与主站统一（token、头部、隐藏重复切换器、代码块深底）
- [ ] /models 筛选器压缩为一行，筛选值补翻译

**P1——两周内（≈ +4~6 分）**

- [ ] 品牌 mark 设计 + 替换模板 logo.png；供应商灰度 logo 行
- [ ] "终端美学" signature 贯穿：控制台 BASE URL 终端卡 + 复制按钮、docs 代码块
- [ ] 错误提示 i18n（错误码→词条）、创建 Key placeholder/分组 tooltip、`USD $` 双标清理
- [ ] 空态统一"一句话 + 次按钮"模式；余额页 primary 唯一化 + 当前余额并入页头
- [ ] 暗色渐变块亮度收敛；认证页合规声明降权 + 卡内加 logo

**P2——持续打磨**

- [ ] 移动端抽屉重设计（导航加大、设置行、CTA 进抽屉）；移动 hero 代码块横滚
