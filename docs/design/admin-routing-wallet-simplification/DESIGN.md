# 管理后台路由与钱包入口收敛设计

日期：2026-07-17

## 事实源

### 模型、映射与价格

- `catalog_model_price` 保存模型五类基准价。
- `catalog_group.newapi_group` 保存门户分组到 New API 分组的一对一映射，`newapi_group_ratio_bps` 保存该分组折扣比例。
- `catalog_model_listing` 保存模型在门户分组中的售卖状态和价格策略。
- 人工维护入口统一位于“模型 → 分组折扣”；网关运营页不再维护第二套映射或价格。

模型可调用必须同时满足：listing 状态可调用、价格策略为继承分组、价格漂移已匹配、分组映射与比例已同步、基准价已同步或人工复核、协议需要的缓存计价维度完整。

### 钱包

- `wallet_account` 是当前余额和冻结状态事实源。
- `wallet_ledger` 是充值、人工调额、请求扣费和冲正的追加式账本。
- `request_ledger` 保存请求用量与结算金额。
- New API quota 和旧 `apipool_ledger_entry` 不参与门户余额计算。

## 请求路由

网关按门户分组和门户模型查询目录配置。生效价格按每个价格维度执行：

```text
effective_micro_usd = ceil(base_micro_usd × group_ratio_bps / 10000)
```

`model_route` 与 `model_price_version` 继续保留，但角色从“人工配置表”改为“内部不可变运行快照”：

1. 热路径先只读检查当前活动快照是否与目录推导结果完全一致；一致则直接复用。
2. 不一致时在事务内退役旧快照并生成下一版本。
3. listing 下线或目录配置不完整时退役活动快照并拒绝路由。
4. `request_ledger` 锁定 `price_version_id`，保证目录改价后历史请求仍可按原版本结算和对账。
5. 并发首次请求遇到唯一约束或 SQLite busy 时重新读取获胜快照，避免重复版本。

## 管理入口

- 网关运营页只保留请求、对账、指标和审计等观测能力。
- 删除路由页签、路由发布/退役 API 及人工路由服务。
- 删除钱包页签；`/admin/apipool-adjustments` 是唯一人工余额修改入口。
- 网关钱包调额 API 只允许基于既有扣费流水做冲正，任意人工金额请求直接拒绝。
- 后台概览资金信号改为本地钱包的透支数和冻结数。

## 支付与调额

- 支付成功时，订单 `paid` 与 `wallet_ledger(recharge)` 在同一数据库事务提交。
- webhook 重放复用既有订单与钱包流水，不触发 New API 兑换码或 quota 写入。
- 人工调额把整美元安全换算为整数 micro-USD，通过钱包账本的幂等键写入，并记录审计。
- 用户详情和 Dashboard 读取本地钱包余额、钱包流水与请求日志。

## 冒烟字段

- 管理表单、服务输入、可调用查询、候选模型选择和静态目录均不再读取或写入 `smokeTested`。
- 旧数据库列暂时保留为迁移兼容字段，避免在同一次逻辑收敛中执行破坏性表重建；它不再影响运行结果。
- 冒烟脚本从满足完整可调用条件的目录模型中选择目标，真实请求结果继续作为发布验证证据。

## 旧设计处理

- 已退出主链路：人工路由发布、网关钱包调额表单、支付后 New API 加额、旧充值重试/对账 API、远端调额后台动作。
- 保留作历史兼容：数据库迁移中的旧列和旧账本表，避免丢失已有审计数据。
- 保留作当前运行必需：路由/价格版本表，但只允许目录驱动自动生成，不再开放人工编辑入口。

## 安全与回滚

- 目录配置不完整时 fail closed，不使用陈旧或半同步价格继续接流量。
- 所有金额使用整数 micro-USD，折扣乘法使用整数向上取整。
- 回滚代码不会自动恢复旧双余额写入；如需回滚管理界面，仍应保持本地钱包唯一事实源。
