# S1：New API 管理员日志接口实测

## 结论

截至 2026-07-15，当前实现机无法从已配置的 New API 管理端 `GET /api/log/` 取得可解析响应，因此不能确认管理员全量日志的实际字段形态。

按 PLAN 的既有裁决，Task 21 采用以下固定策略：

1. 优先调用管理员全量日志接口。
2. 管理员接口请求失败时，立即回退为逐绑定用户调用 `/api/log/self`。
3. `request_id` 同时兼容日志顶层字段和 `other` JSON 内字段；不得仅依赖未经实测确认的单一位置。

## 脱敏实测证据

- 配置完整性：本地部署环境已配置 `NEWAPI_BASE_URL`、管理员 token 和管理员用户 ID；实测过程未输出任何配置值。
- Node `fetch`：请求失败，底层错误码为 `UND_ERR_SOCKET`，未取得 HTTP 响应体。
- curl 独立复核：退出码为 52（服务端空响应），同样未取得字段体。
- 两次请求均为只读 GET；未执行写操作、部署或切流。

## 实现边界

- 本次结论只说明当前实现机无法验证管理员接口，不推断生产接口永久不可用。
- Task 21 必须保留管理员主路径，运行时失败后使用逐绑定兜底；不能调用不透传时间范围的旧 `listUsageLogs`。
- 后续若在受信网络取得管理员日志 fixture，应新增 fixture 测试固定字段形态，不回写本调研记录。
