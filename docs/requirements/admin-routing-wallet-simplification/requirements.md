# 管理后台路由与钱包入口收敛需求

日期：2026-07-17

## 背景

管理后台同时存在“模型分组折扣”和“网关运营路由”两套分组、映射及价格配置，也同时存在“网关运营钱包”和“APIPool 调额”两个余额修改入口。重复配置会产生相互矛盾的事实源，运营人员无法判断哪一处最终影响请求路由和用户余额。

此外，“冒烟测试通过”被设计成人工开关，但它不能证明模型在当前运行环境真实可用，反而容易成为形式化的发布门槛。

## 目标

- 模型元数据维护基准价格；模型下的分组折扣维护门户分组到 New API 分组的唯一映射及折扣策略。
- 网关请求根据模型目录和分组折扣自动得到上游分组、模型与生效价格，不再要求运营手工发布第二套路由和价格。
- 用户余额只由 APIPool 本地钱包维护，管理后台只保留“APIPool 调额”一个人工调额入口。
- 删除“冒烟测试通过”人工选项；模型可调用性由目录状态、映射、价格同步和必要价格维度共同决定。
- 清查旧门户/New API 双余额、双分组和双账本设计，退出当前主链路。

## 非目标

- 不删除已有数据库迁移历史。
- 不删除请求结算所需的不可变路由、价格版本和历史请求账本。
- 不改变 New API 自身原生直连账户的 quota 管理能力。
- 不在本次变更中执行生产发布或修改生产数据。

## 验收标准

- 网关运营页不再展示路由配置和钱包调额页签。
- 分组折扣保存门户分组到 New API 分组的映射，模型基准价与分组比例可推导出请求价格。
- 第一次请求可自动生成运行时路由和价格快照；目录配置变化时自动生成新版本，历史请求仍引用旧版本。
- APIPool 调额写入本地钱包，不修改 New API quota；网关内部接口拒绝任意人工加减余额。
- 支付成功只写一条本地钱包充值流水，不写旧 `credit` 或 New API 加额账本。
- 分组折扣表单、服务层和可调用性查询均不依赖 `smokeTested`。
- 后台概览、用户详情、Dashboard 和公开用量接口均以本地钱包与请求账本为准。
