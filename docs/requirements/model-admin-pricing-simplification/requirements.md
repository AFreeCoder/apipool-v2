# 管理后台模型管理与分组折扣简化需求

日期：2026-07-08

## 背景

管理后台的模型目录已经把模型主数据、模型基准价格和分组维度 listing 串起来，但当前页面表达仍偏底层：

- 模型管理列表同时展示模型基础信息、默认分组、折扣和 `pricingStatus` 拼接状态。
- 模型新增/编辑表单同时维护模型主数据、默认分组、折扣和说明。
- “模型售卖项”页面直接暴露 listing、价格、划线价、`smokeTested`、排序等字段。
- `pricingStatus` 由 base/group/policy 内部状态拼接，对管理员不可读。

用户期望模型管理页面只维护官方正价模型清单；不同分组的折扣配置从“售卖项”概念中抽出来，以“分组折扣”表达。

## 目标

- 模型管理列表聚焦官方正价模型清单，只展示：
  - 模型 ID
  - 模型名称
  - 供应商
  - 分类
  - 能力
  - 输入价格
  - 输出价格
  - 图片输入价格
  - 图片输出价格
- 模型新增/编辑表单聚焦模型主数据和官方基准价格，不再把分组、折扣说明、模型说明作为主流程字段。
- “模型售卖项”后台文案统一改为“分组折扣”，路由和底层 `catalog_model_listing` 保持不变。
- 分组折扣新增/编辑页面聚焦分组、状态、折扣、折扣说明和必要运维验证字段。
- 模型列表移除“价格同步状态”列，保留现有价格同步/漂移操作入口。
- 不做数据库 schema 重构，不删除 `catalog_model_listing`、`smokeTested` 或价格同步字段。

## 评审约束

本需求按执行 agent + 评审 agent 机制分析后，接受以下约束：

- `catalog_model_listing` 仍被公开 `/models`、可调用模型查询和 smoke 使用，不能删除底层语义。
- `smokeTested` 对普通管理员不好懂，但 smoke 脚本依赖它挑选模型；本次不在列表展示，但在分组折扣表单保留为“运维烟测通过”字段，并补说明。
- 分组折扣表单不能把普通折扣直接落成未验证的 `listing_multiplier` 公开价；后端继续保留现有 `inherit_group`/价格同步确认逻辑。
- API Key 创建仍只依赖分组状态、`allowCreateKey` 和 `newapiGroup`，本次不修改分组管理语义。

## 范围

包含：

- 管理后台模型列表列集合调整。
- 模型表单字段降噪。
- listings 页面文案改为分组折扣。
- 分组折扣列表和表单字段降噪。
- 中英文 i18n 文案同步。
- 覆盖页面静态约束的测试更新。

不包含：

- 数据库表重命名或迁移。
- 公开 `/models` 展示逻辑重构。
- New API 价格同步算法调整。
- API Key 创建、分组权限、live smoke 脚本重构。
- 发布或生产数据变更。

## 验收标准

- 模型管理列表不再出现分组、折扣、价格同步状态列。
- 模型新增/编辑页面不再展示分组、折扣、折扣说明、说明字段。
- 模型新增/编辑仍能保存模型主数据、分类、能力和四类基准价格。
- 模型操作菜单中的售卖项入口显示为“分组折扣”。
- 分组折扣列表不再展示输入/输出价格、划线价、`smokeTested`、排序等底层字段。
- 分组折扣新增/编辑不再要求管理员手填最终输入/输出价；价格继续来自模型基准价和既有同步策略。
- 分组折扣表单保留“运维烟测通过”字段，并说明它只影响发布 smoke 候选。
- 现有公开模型查询、API Key 分组创建和 smoke 依赖不因本次 UI 简化回归。
