# 分组定价档案需求

## 背景

当前模型元数据同时保存模型事实和售卖计费方式，导致同一模型在不同分组下只能共享
`token` 或按次计费。图片、视频和音频模型在不同分组中可能采用不同售卖方式，因此计费
方式不能由模型全局元数据决定。

售卖计费与上游成本计费是两个独立领域。上游成本变化、缺失或采用不同计费方式，不得
修改、隐藏或阻断已经人工确认的售卖价。

## 目标

- 模型元数据只维护模型身份、分类和能力，不维护售卖计费方式或售卖价格。
- 每条“模型 × 分组”售卖项明确选择一个模型级可复用定价档案。
- 同一模型的不同分组可以选择不同计费方式和不同价目表。
- 支持的售卖计费方式：
  - LLM、Embedding：仅 Token。
  - 图片：Token、按次。
  - 视频、音频：Token、按次、按时长。
- 分组折扣是对所选定价档案的唯一售卖折扣，发布快照保存折后价格。
- 图片按次结算数量以成功响应中的实际图片数量为准，不相信请求中的 `n`。
- 按时长结算数量必须来自受信任的响应或 usage 数据，SKU 规则不得计算数量。
- 上游成本同步仅生成独立成本参照和变化报告，不参与售卖发布、可调用性或扣费。

本期只打通图片模型的 Token 与按次计费。按时长档案继续保留配置校验、金额计算和自动化
测试，但在接入首个真实音频或视频模型前，不要求线上端到端验收，也不对外宣称按时长链路
已经可用。

## 异步执行与结果交付

- 对采用任务协议的图片模型，APIPool 公共 API 采用异步契约：提交返回 APIPool 自己的
  任务 ID，用户通过任务查询接口读取状态和结果。
- `POST /v1/images/generations` 的 JSON 文生图/URL 图生图，以及
  `POST /v1/images/edits` 的 multipart 图生图统一进入异步任务；原始请求参数和文件字节由
  APIPool 原样转发给 New API 的 APIMart 图片任务适配器。
- 用户查询只读取 APIPool 已持久化的任务状态，不把每次用户轮询直接放大为一次上游
  查询 APIMart；APIPool 后台负责持续查询 New API 并补偿中断任务。
- 上游成功后，必须先由 New API 把所有图片搬运到平台控制的 R2，再向 APIPool 返回完成态。
- 对外只返回 New API 从 R2 新签发、由 APIPool 透出的对象存储链接，不返回 APIMart 临时
  链接，也不在 APIPool 再复制一份相同文件。
- 按次计费数量以 New API 已成功写入 R2、实际可交付的图片数为准。部分搬运失败时不得
  部分完成或提前扣费。
- New API 的 R2 未配置或搬运失败时，任务不能进入完成态；超过补偿边界后失败且不向用户
  扣费，上游成本由平台承担。

## SKU 规则

- 按次和按时长档案可以配置受限规则表达式，根据已声明的请求事实选择 SKU。
- 规则只能读取允许字段、比较常量并返回 SKU；不能访问网络、文件、数据库、环境变量或
  当前时间，不能执行任意 JavaScript。
- 规则保存时必须编译和校验；运行时只执行已编译的确定性结构。
- 规则只能选择 SKU 或拒绝请求，不能计算单价、数量或最终金额。
- 规则选择出的 SKU 必须存在于当前定价档案，否则请求在转发前失败。

## 兼容性边界

- 售卖、公开目录、发布快照和网关扣费只能读取定价档案，不建设旧售价字段的双读或双写层。
- 已存在的 listing 必须选择同模型的有效定价档案；缺少档案时不得发布或调用。
- 历史上游成本字段可以继续作为只读成本参照缓存，但不得再被当作售卖价。

## 验收标准

- 管理员在模型元数据表单中看不到计费方式和售卖价格。
- 管理员可以为模型创建、编辑、删除未被引用的定价档案。
- listing 新建和编辑表单必须选择定价档案，并继续支持分组折扣。
- 不合法的“模型分类 × 计费方式”、费率、计量单位或 SKU 规则不能保存。
- Token、按次和按时长的金额计算都有边界与舍入测试。
- JSON 与 multipart 图片请求都能用同一 SKU 规则选档。
- 图片按次请求按实际返回张数扣费，并覆盖默认 SKU、明确 SKU、未知 SKU 和中断响应。
- 异步图片提交返回 APIPool 任务 ID；任务查询覆盖处理中、搬运中、完成、上游失败、
  搬运失败、缺失计量和重复查询。
- 完成响应中的每个图片 URL 都是仍在有效期内的 R2 签名链接，携带过期时间，且任务完成前
  对象已可读取；结果保留期内重新查询可以获得新链接。
- 用户任务查询不能跨用户或跨 API Key；重复轮询、后台补偿和并发终态处理最多结算一次。
- 成本同步变化不会改变售卖快照、公开价或 listing 可调用性。
- 完成单元、集成、迁移、类型、lint、构建和本地冒烟测试。
- 部署后用内置浏览器真实验证官方分组与 Codex 特惠分组的 API 请求。
